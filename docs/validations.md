# Validations in the system

Every rule that checks or limits input, grouped by microservice, with the class or file that enforces it.

**How to read this:**
- **Rule** is what is checked. **Response** is what the caller gets when it fails.
- **Where** gives the class (or file) and, where useful, the line in the current code.
- Validation is done in layers. The same rule often appears in the form, the service and the database. The service layer is the one that matters; the form only gives early feedback.
- The sign-in, JWT and role checks have been written but, at the time of writing, had not been compiled or run. Treat them as designed behavior until tested.

## 1. employee-service (Java)

### 1.1 Add an employee: format rules

Class: `dto/CreateEmployee` (annotations). Text fields are trimmed by its compact constructor before the checks run. A failure returns **400** with a message per field (`fieldErrors`). When a field breaks several rules, only the most basic one is kept (required, then length, then number rules, then pattern), chosen by `EmployeeController.formatErrors`.

| Field | Rule | Annotation | Message |
|---|---|---|---|
| fullName | Required | `@NotBlank` | fullName is required |
| fullName | 2 to 160 characters | `@Size(min=2, max=160)` | fullName must be 2 to 160 characters |
| fullName | Letters and single spaces only; a period is allowed only in a final `Jr.` or `Sr.` (any capitalization) | `@Pattern` | fullName may contain only letters and spaces (a period is allowed only in the suffix Jr. or Sr.) |
| position | Required | `@NotBlank` | position is required |
| emailAddress | Required | `@NotBlank` | emailAddress is required |
| emailAddress | At most 254 characters | `@Size(max=254)` | emailAddress must be at most 254 characters |
| emailAddress | Must look like `name@pwc.com`, any capitalization | `@Pattern` (case-insensitive) | emailAddress must be a valid address ending in @pwc.com |
| contactNumber | Required | `@NotBlank` | contactNumber is required |
| contactNumber | `+63` followed by exactly 10 digits | `@Pattern` | contactNumber must start with +63 followed by 10 digits, e.g. +639171234567 |
| baseSalary | Required | `@NotNull` | baseSalary is required |
| baseSalary | Greater than 0 | `@DecimalMin(0, inclusive=false)` | baseSalary must be greater than 0 |
| baseSalary | At most 9,999,999,999,999.99 | `@DecimalMax` | baseSalary is too large |
| baseSalary | At most 13 whole digits and 2 decimal places | `@Digits(integer=13, fraction=2)` | baseSalary can have at most 2 decimal places |

### 1.2 Add an employee: rules that need other data

Class: `service/EmployeeService.validate` (merges these with the format errors above; one message per field, in form order).

| Rule | Detail | Message |
|---|---|---|
| Position is an allowed value | Associate, Senior Associate or Manager | position must be one of: Associate, Senior Associate, Manager |
| E-mail not already used by an employee | Compared in lowercase; asks `EmployeeRepository.existsByEmail`. Skipped if the e-mail already has a format error | emailAddress is already used by another employee |
| Salary fits the position | Associate 20,000-60,000; Senior Associate 60,001-100,000; Manager 100,001 and above. Skipped if the position or salary already failed. Uses exact decimal comparison (`salaryRangeError`) | baseSalary for Associate must be between 20,000 and 60,000 (and similar) |

Other handling in `controller/EmployeeController`:

| Rule | Response |
|---|---|
| Request body is missing | 400 Request body is required |
| Two requests with the same e-mail pass the check at the same time; the database rejects the second (`DuplicateKeyException`) | 409 emailAddress is already used by another employee |
| Employee id in the URL does not exist (get, delete) | 404 |

### 1.3 Add an employee: database constraints (last line of defence)

File: `resources/schema.sql`, table `employees`.

| Constraint | Rule |
|---|---|
| `position CHECK` | Only the three allowed positions |
| `email_address CHECK` and `uq_employees_email` | Must end in `@pwc.com`; must be unique |
| `chk_email_lowercase` | Stored lowercase, which makes uniqueness case-insensitive |
| `contact_number CHECK` | Must start with `+63` |
| `base_salary CHECK` | Greater than 0 |
| `chk_salary_by_position` | Salary range for each position |
| `employee_code` UNIQUE and NOT NULL | No two employees share a code (the code is generated by a sequence) |
| `NOT NULL` on every column | No missing values |

### 1.4 Sign-up, login, forgot password, reset password

| Rule | Where | Response |
|---|---|---|
| Sign-up: e-mail required, at most 254 characters, `@pwc.com` | `dto/SignUpRequest` (`@NotBlank`, `@Size`, `@Pattern` using `dto/AuthPatterns.PWC_EMAIL`) | 400 with a message per field |
| Sign-up: password required, 8 to 100 characters | `dto/SignUpRequest` (`@NotBlank`, `@Size`) | 400 |
| Sign-up: e-mail not already registered | `service/AuthService.signUp` (`existsByEmail`, plus a `DuplicateKeyException` catch for simultaneous requests) | 409 emailAddress is already registered |
| Sign-up: role is always `member` | `service/AuthService.signUp` (the request has no role field) | Cannot sign up as an admin |
| Login: e-mail and password present | `dto/LoginRequest` (`@NotBlank` on both) | 400 |
| Login: correct e-mail and password | `service/AuthService.login`. Wrong e-mail and wrong password give the same message; the hash is checked even for an unknown e-mail so timing does not reveal which accounts exist | 401 Invalid email or password |
| Login and reset: lock-out after repeated failures | `security/AttemptTracker` (5 failures lock that key for 15 minutes; at most 10,000 keys tracked), applied in `AuthService.login` and `AuthService.resetPassword` | 429 Too many failed attempts |
| Forgot password: e-mail required, at most 254 characters, `@pwc.com` | `dto/ForgotPasswordRequest` | 400 |
| Forgot password: same answer whether or not the account exists | `controller/AuthController.forgotPassword` | 200 with the same message |
| Reset: e-mail rules, code required, new password required and 8 to 100 characters | `dto/ResetPasswordRequest` | 400 |
| Reset: code exists, has not expired (15 minutes) and matches; compared in constant time; single use | `service/AuthService.resetPassword` | 400 Invalid or expired reset code |
| Password stored only as a salted hash | `security/PasswordHasher` (PBKDF2-HMAC-SHA512, 210,000 rounds, random 16-byte salt, constant-time compare, tolerates damaged stored values) | n/a |

Database (`users`, `password_resets` in `schema.sql`): unique and lowercase `@pwc.com` e-mail; role limited to `admin` or `member`; reset code row tied to an existing user with cascade delete.

There is no password complexity rule. Only the length is checked.

### 1.5 Tokens (JWT) and access control

| Rule | Where | Response |
|---|---|---|
| Signing secret is present and at least 32 characters; token lifetime at least 1 minute | `security/JwtService` constructor | Service refuses to start |
| Token is present, not blank, at most 2,048 characters | `JwtService.verify` | 401 |
| Valid signature; only HS256 accepted | `JwtService.verify` | 401 |
| Not expired | `JwtService.verify` | 401 |
| Issuer and audience match this app | `JwtService.verify` | 401 |
| Subject (user id), e-mail and role present | `JwtService.verify` | 401 |
| `Authorization: Bearer <token>` format | `security/BearerToken` | 401 |
| Signed in to read employees | `security/AuthInterceptor` (on `/api/employees` and `/api/employees/**`) | 401 Sign in required |
| Admin role to add or delete an employee | `security/AuthInterceptor` (any request that is not GET or HEAD) | 403 Admin access required |
| Browser pre-flight (`OPTIONS`) is let through | `security/AuthInterceptor` | n/a |
| Only `http://localhost:5173` may call from a browser | `@CrossOrigin` on `EmployeeController` and `AuthController` | Browser blocks the call |

## 2. payroll-service (Node.js)

### 2.1 Run payroll

Class: `services/payroll.service.js`, function `runPayroll` (one 400 message for all input problems).

| Rule | Response |
|---|---|
| `employeeId` is a positive whole number | 400 Provide a positive employeeId, YYYY-MM period, overtimeHours from 0 to 100, and nonnegative deductions |
| `period` is text in the form `YYYY-MM` with a month of 01-12 | 400 (same message) |
| `overtimeHours` is a number from 0 to 100 and finite | 400 (same message) |
| `deductions` is a number of 0 or more and finite | 400 (same message) |
| Employee exists (`services/employee.client.js`) | 404 Employee not found |
| Employee service returns a positive, finite salary | 502 Employee service returned invalid salary data |
| Total deductions (contributions + tax + other) do not exceed gross pay | 400 Deductions cannot exceed gross pay |
| Only one run per employee per month; the check and the save happen in one queued step (`repositories/payroll.repository.js`, `insertUnique`) | 409 Payroll already exists for this employee and period |
| JSON request body at most 32 KB | `app.js` (`express.json`), setting in `config/index.js` | Request rejected (the error handler answers 500; see gaps) |

### 2.2 Export

| Rule | Where | Response |
|---|---|---|
| Payroll record id must exist | `payroll.service.js`, `exportRun` | 404 Payroll record not found |
| Quotes inside values are doubled so CSV cells cannot break | `payroll.service.js`, `exportRun` | n/a |

### 2.3 Employee photos

Class: `services/image.service.js`.

| Rule | Function | Response |
|---|---|---|
| Employee id is a positive safe integer made only of digits | `parseEmployeeId` | 400 employeeId must be a positive integer |
| AWS is switched on and a bucket is configured | `ensureAvailable` | 503 Image storage unavailable |
| Request body is a non-empty file | `upload` | 400 Send the image file as the request body |
| Real file type is JPEG, PNG or WebP, read from the file's first bytes (the declared type is ignored) | `detectType` | 400 Image must be a JPEG, PNG or WebP file |
| File is at most 2 MB | `routes/image.routes.js` (`express.raw`, `imageBodyErrors`) | 413 Image must be 2 MB or smaller |
| The employee exists | `upload`, via `employee.client.js` | 404 / 502 |
| S3 call fails | `storageFailure` (real cause is logged, user sees a generic message) | 503 Image storage unavailable |
| Only photo keys of the form `employees/<digits>/photo` are listed | `repositories/image.repository.js`, `listEmployeeIds` | n/a |

### 2.4 Access control and start-up

| Rule | Where | Response |
|---|---|---|
| `JWT_SECRET` present and at least 32 bytes | `config/index.js` | Service refuses to start |
| Every `/api` call needs a valid JWT: HS256 only; signature, expiry, issuer and audience checked; subject, e-mail and role present; token at most 2,048 characters | `middleware/auth.js`, `requireUser` (mounted in `routes/index.js`; `/health` stays open) | 401 Sign in required |
| Admin role to run payroll | `requireAdmin` on `POST /api/payroll/run` (`routes/payroll.routes.js`) | 403 Admin access required |
| Admin role to upload or delete a photo | `requireAdmin` on `routes/image.routes.js` (runs before the upload is read) | 403 |
| Admin role for the AWS status | `requireAdmin` on `routes/aws.routes.js` | 403 |
| Browser pre-flight (`OPTIONS`) is let through | `middleware/auth.js` | n/a |
| Only `http://localhost:5173` may call from a browser | `app.js` (`cors`), setting in `config/index.js` | Browser blocks the call |
| AWS status is masked (last 4 account digits; user and role names hidden) | `services/aws.service.js` | n/a |
| Unexpected errors hide their details | `middleware/error-handler.js` | 500 Internal server error |

## 3. ai-service (Python)

### 3.1 Payroll review request

Class: `schemas/payroll.py` (Pydantic). Any failure returns **400 Malformed payroll records** from `api/analysis.py`. A body that is not a JSON object at all is refused earlier by FastAPI with 422.

| Field | Rule | Reason |
|---|---|---|
| `baseSalary` | Greater than 0 | Used as a divisor |
| `grossPay` | Greater than 0 | Used as a divisor |
| `overtimeHours`, `overtimePay`, `deductions`, `netPay` | 0 or more | Negative amounts make no sense |
| All six numbers | Finite (no Infinity, no NaN); `PayrollRecord.finite_numbers` | These pass "greater than 0" but break the maths |
| Numbers sent as text | Accepted and converted (`"30000"` becomes 30000) | Pydantic default |
| Unknown fields on a record | Kept (the `id` is read back) | `extra="allow"` |
| Unknown top-level keys beside `records` | Rejected | `AnalyzeRequest` has `extra="forbid"` |
| `records` is a list | Required; an empty list is allowed | `AnalyzeRequest` |

### 3.2 Fixed review rules

Class: `services/analysis.py`, function `rule_warnings`. These do not reject input; they add a warning and mark the record `review`.

| Rule | Warning |
|---|---|
| Overtime above 24 hours | `overtime_hours_exceed_24` |
| Deductions above 20% of gross pay | `deductions_exceed_20_percent_of_gross` |
| Gross minus deductions differs from net by more than 0.01 | `gross_minus_deductions_does_not_match_net` |

### 3.3 Chat request

Class: `schemas/chat.py` (Pydantic). Any failure returns **400 Invalid chat request** from `api/chat.py`.

| Rule | Reason |
|---|---|
| 1 to 12 messages | Limits cost and misuse |
| Each message 1 to 1,000 characters | Same |
| Role is `user` or `assistant` only | A caller cannot slip in a `system` message to change the rules |
| No extra keys on a message or the request | `extra="forbid"` |
| The last message must be from the user (`ChatRequest.last_message_is_from_user`) | There must be a question to answer |

### 3.4 Chat processing

| Rule | Where | Response |
|---|---|---|
| OpenAI key is configured | `services/chat.py` | 503 OpenAI is not configured |
| At least one data source (employees or payroll) loaded | `services/data_source.py` raises `DataUnavailable` | 502 |
| OpenAI call succeeded and returned an answer | `services/chat.py` | 502 OpenAI request failed / declined to answer |
| Only the listed employee and payroll fields are passed on; newest 200 runs only | `services/data_source.py` | n/a |
| Answers limited to the supplied data and on-topic | System prompt in `services/chat.py`. **Enforced by instructions to the model, not by code** | Model replies "I can't find that in the payroll data" or declines |

### 3.5 Access control and start-up

| Rule | Where | Response |
|---|---|---|
| `JWT_SECRET` present and at least 32 bytes | `core/config.py` | Service refuses to start |
| Every `/api/ai/...` call needs a valid JWT: HS256 only; `exp`, `sub`, `iss` and `aud` required; issuer and audience must match; `email` and `role` present; token at most 2,048 characters | `core/auth.py`, `current_token` (applied to the whole router in `api/analysis.py`, and as a parameter in `api/chat.py`) | 401 Sign in required |
| Any signed-in user may use review and chat (the role is not checked) | `core/auth.py` | n/a |
| Allowed browser origin, methods and headers: `http://localhost:5173`, GET and POST, `Content-Type` and `Authorization` | `core/config.py`, applied in `main.py` | A missing header here caused the `OPTIONS ... 400` error |
| OpenAI replies are read as strict JSON of the expected shape | `services/openai_review.py` | Falls back to the fixed rules |

## 4. Front end (React)

File: `frontend/src/App.jsx`. These checks give instant feedback only. The services repeat them, because anyone can call the API directly.

| Rule | Function or element |
|---|---|
| Employee form: the same name, position, e-mail, contact number and salary rules as 1.1 and 1.2 (position-based salary range), shown under each field, all at once | `validateEmployee`, `SALARY_RANGES` |
| Contact number is forced to start with `+63`; non-digits are removed | The contact number input's change handler |
| Sign-in screens: e-mail required; sign-up and reset also need a `@pwc.com` e-mail, a password of at least 8 characters, and matching confirmation; reset also needs the code | `validateCredentials`, `EMAIL_PATTERN` |
| Photo must be JPEG, PNG or WebP and at most 2 MB | `PHOTO_TYPES`, `PHOTO_MAX_BYTES` in the photo handler |
| Field length limits on inputs (for example name 160, e-mail 254) | `maxLength` on the inputs |
| Chat messages are limited to 1,000 characters | `maxLength` on the chat input |
| A 401 from any service ends the session and returns to sign-in; the session also ends when the token's expiry passes | `request` helper and `Root` |
| Admin-only controls are hidden from members | The `isAdmin` flag (a convenience only; the services enforce roles) |

## 5. Rules that exist in more than one place

Changing any of these means editing every place listed.

| Rule | Places |
|---|---|
| Salary range by position | `App.jsx` (`SALARY_RANGES`), `EmployeeService.salaryRangeError`, `schema.sql` (`chk_salary_by_position`) |
| Allowed positions | `App.jsx`, `EmployeeService.POSITIONS`, `schema.sql` |
| `@pwc.com` e-mail | `App.jsx`, `CreateEmployee`, `AuthPatterns` (sign-up, forgot, reset), `schema.sql` (employees and users) |
| `+63` plus 10 digits | `App.jsx`, `CreateEmployee`; the database only checks the `+63` start |
| Name pattern | `App.jsx`, `CreateEmployee` |
| Password length 8-100 | `App.jsx`, `SignUpRequest`, `ResetPasswordRequest` |
| JWT issuer, audience and algorithm | `JwtService.java`, `payroll-service/src/config/index.js` and `middleware/auth.js`, `ai-service/app/core/config.py` and `core/auth.py` |
| `JWT_SECRET` present and at least 32 characters | `JwtService.java`, `payroll-service/src/config/index.js`, `ai-service/app/core/config.py`; the same value must be in each service's `.env` |
| 2 MB photo limit | `App.jsx`, `routes/image.routes.js` (setting in `config/index.js`) |

## 6. Known gaps

- **Name rule:** letters and spaces only, so hyphens and apostrophes (`Mary-Ann`, `O'Neil`) are rejected.
- **Passwords:** only the length is checked, not complexity. The seeded admin password (`admin`) is shorter than the 8-character minimum for new passwords.
- **Payroll input:** `employeeId` accepts values such as `"1"` or `true` because they convert to a number. Malformed JSON in a request gives a 500 instead of a 400.
- **Contact number:** the database only checks the `+63` start; the exact 10 digits are checked in the DTO and the form.
- **Chat scope:** the data-only and on-topic rule depends on the model following instructions.
- **Tokens:** a JWT cannot be cancelled before it expires, so sign-out, password reset and role changes do not affect tokens already issued.
- **Duplicated rules:** see section 5; the risk is that the copies drift apart.
